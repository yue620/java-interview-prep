**1. 创建线程的方式？Runnable 和 Callable 的区别？**

四种：继承 Thread、实现 Runnable、实现 Callable + FutureTask、线程池。
区别：① Runnable 的 run() 无返回值，Callable 的 call() 有返回值；② Callable 能抛受检异常，Runnable 不能；③ Runnable 直接传给 Thread，Callable 必须包 FutureTask（FutureTask 同时实现 Runnable 和 Future，既能 start 又能 get）。

**2. 为什么推荐 Runnable 而不是继承 Thread？**

① Java 单继承，extends Thread 占掉唯一继承名额；② 任务与线程解耦（组合优于继承），同一个任务可给多个线程复用；③ 线程池的 submit 只收 Runnable/Callable，继承 Thread 进不了池子。
（追问：Thread 本身也实现了 Runnable，继承重写 run 本质还是填 Runnable 的 run。）

**3. start() 和 run() 的区别？start() 调两次？**

start() 让 JVM 创建新线程异步执行 run；直接 run() 只是当前线程里的普通方法调用，不产生新线程。
start() 只能调一次，调两次抛 IllegalThreadStateException——Thread 对象是一次性的，状态从 NEW 出去就回不来；任务（Runnable）可以复用，线程不行。

**4. 六种状态？BLOCKED 和 WAITING 的区别？**

NEW / RUNNABLE / BLOCKED / WAITING / TIMED_WAITING / TERMINATED。
BLOCKED：抢 synchronized 锁失败，被动等在锁门口，拿到锁自动回 RUNNABLE。
WAITING：主动调 wait()/join()，放弃锁等条件，必须被 notify 并重新抢到锁才继续。
TIMED_WAITING：sleep(ms)/wait(ms)，到点自己醒。

**5. sleep() 和 wait() 的区别？（五维度）**

① 归属：sleep 是 Thread 静态方法，wait 是 Object 方法（lock.wait()）；② 位置：sleep 任意处可用，wait 必须在 synchronized 内（否则 IllegalMonitorStateException）；③ 锁：sleep 不释放锁，wait 释放锁；④ 唤醒：sleep 到点自醒，wait 靠 notify + 重新抢锁；⑤ 用途：sleep 单纯延时，wait/notify 线程间协调。

**6. synchronized 三种用法锁的对象？**

① 代码块：锁括号里指定的对象；② 实例方法：锁 this；③ 静态方法：锁该类的 Class 对象。
（铁律：必须所有线程抢同一把锁才有效。）

**7. 锁升级过程？为什么这样设计？**

无锁 → 偏向锁 → 轻量级锁 → 重量级锁，只升不降，状态记录在对象头 MarkWord。
动机：重量级锁的阻塞/唤醒要切换内核态，开销大；而现实中大多数锁竞争不激烈。无竞争用偏向（记线程 ID 零开销），轻竞争用轻量级（自旋不阻塞），真激烈才重量级（内核排队）。省的是内核态切换开销，不是内存。

**8. 三种锁的场景？状态记在哪？**

偏向锁：始终只有一个线程使用锁；轻量级锁：出现竞争但线程交替执行、自旋能等到；重量级锁：竞争激烈/自旋失败/持有时间长，失败者阻塞。状态记录在对象头的 MarkWord。

**9. volatile 保证哪两件事？**

① 可见性：写后立即刷回主存，读时强制从主存读，其他线程立刻看到最新值；② 禁止指令重排：通过内存屏障实现。

**10. volatile 保证原子性吗？count++ 为什么出问题？**

不保证。count++ 是"读→加→写"三步非原子操作，volatile 只保证读到最新值，两个线程可同时读到同一值后各加各的，丢更新。解决：synchronized 或 AtomicInteger（CAS）。

**11. DCL 单例三个为什么？**

① 两次 null 检查：第一次挡掉已创建后的所有调用（免抢锁），第二次防两线程同时通过第一次检查后重复创建；② volatile 不能省：new 对象分"分配内存→初始化→引用指向"三步，可能重排成"分配→指向→初始化"，其他线程会拿到未初始化的半成品，volatile 禁止该重排；③ 构造私有：防止外部 new 出第二个实例。
（加分：单例用途——配置/线程池/连接池/缓存；Spring Bean 默认单例。）

**12. synchronized 和 volatile 的区别？**

① 功能：synchronized 保证原子性+可见性，volatile 只保证可见性+禁重排，不保证原子性；② 阻塞：synchronized 会阻塞线程，volatile 不会，更轻量；③ 修饰范围：synchronized 可修饰方法/代码块，volatile 只能修饰变量；④ 场景：复合操作（count++）用 synchronized，状态标记（flag）用 volatile。
