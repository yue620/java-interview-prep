# Day 12 自测清单答案（采分点版）

**1. 秒杀架构（采分层次）**
- 核心思想一句话：**把压力挡在数据库前面**
- 漏斗各层：前端限流/答题 → 网关限流 → **Redis 原子预减库存** → **MQ 削峰** → 消费者匀速落库
- 细节加分：防超卖双保险、幂等（唯一索引/SETNX）、库存预热、降级兜底

**2. Redis 和 MQ 的角色**
- Redis：**扛瞬时高并发读写的原子扣减**（内存 + 单线程原子操作）
- MQ：**削峰填谷 + 异步解耦**，把瞬时洪峰变成匀速消费
- 没有 MQ：Redis 扣完直接同步写库，DB 依然承受洪峰 → 失去缓冲，高并发下会挂

**3. 消息丢失三环节**
- 生产端：**confirm 确认机制** + 失败重发
- MQ 端：消息**持久化** + 集群多副本
- 消费端：**手动 ack**，处理成功才确认，失败重投（→ 由此引出幂等需求）

**4. 幂等性**
- 同一操作执行多次和执行一次效果相同
- MQ 至少一次投递 → 重复消费是常态 → 消费者必须幂等
- 手段：**业务唯一键 + 数据库唯一索引**；**Redis SETNX**（处理前占位，成功才继续）；去重表

**5. MQ 产品对比**
- RocketMQ：Java、功能全（延迟/事务消息），互联网业务常用
- Kafka：吞吐之王，日志采集/大数据
- RabbitMQ：低延迟、易用，中小规模

**6. 分布式事务**
- 方案：2PC（强一致性能差）、TCC（预留-确认-取消，资金类）、**本地消息表**、**MQ 事务消息**、Seata
- 实际选择：大多接受**最终一致性**，本地消息表/MQ 事务消息 + 重试 + 对账兜底；强一致代价太高

**7-8. 自我介绍 / STAR（评分点）**
- 60 秒内；有技术定位句；项目部分留"钩子"引导追问；提及真实成果
- STAR 四段完整，A（行动）部分占比最大，R（结果）有量化
- 主动提到的每个技术词都能经得起追问

**9. Redis 一致性追问（满分框架）**
- 说清楚 Cache Aside：读先缓存后 DB 回填；写先更 DB 再删缓存
- 被追问不一致窗口 → 延迟双删 / Canal binlog 兜底
- **前提：回答必须基于 paismart 真实实现，没做过就说"设计过方案但没上线，在练习项目 mini-mall 里完整实现过"——诚实但展示了能力**

**10. 最大难点（万能结构）**
- 现象（出了什么问题）→ 定位过程（怎么排查的，用了什么工具/日志）→ 根因 → 解决方案 → 验证结果
