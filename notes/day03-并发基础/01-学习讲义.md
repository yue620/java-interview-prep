## 一、创建线程的方式（面试第一问，别只说两种）

### 1.1 四种方式

**① 继承 Thread，重写 run()**

```java
class MyThread extends Thread {
    @Override public void run() { System.out.println("跑"); }
}
new MyThread().start();
```

**② 实现 Runnable，传给 Thread**（推荐）

```java
new Thread(() -> System.out.println("跑")).start();
```

**③ 实现 Callable + FutureTask（能拿返回值）**

```java
Callable<Integer> task = () -> { return 42; };
FutureTask<Integer> ft = new FutureTask<>(task);
new Thread(ft).start();
Integer result = ft.get();   // 阻塞等结果
```

**④ 线程池**（生产环境唯一正确姿势，Day 4 详讲）

```java
ExecutorService pool = Executors.newFixedThreadPool(4);
pool.submit(() -> System.out.println("跑"));
```

### 1.2 高频追问

**Q：Runnable 和 Callable 的区别？**

| | Runnable | Callable |
|---|---|---|
| 返回值 | 无 | **有**（`call()` 返回 V） |
| 抛异常 | 不能抛受检异常 | **可以** |
| 配套 | 直接给 Thread | 要包 FutureTask 或交给线程池 |

**Q：为什么推荐实现 Runnable 而不是继承 Thread？**
Java 单继承，继承了 Thread 就不能继承别的类；实现接口更灵活，而且把"任务"和"执行机制"解耦。

**Q：start() 和 run() 的区别？（超级高频）**
`start()` 才真正**创建新线程**并异步执行 run；直接调 `run()` 只是**当前线程**里普通的方法调用，没有新线程。start() 只能调一次，调两次抛 `IllegalThreadStateException`。

## 二、线程的生命周期（六种状态）

```
        start()
新建 ──────────→ 就绪/运行（RUNNABLE）
(NEW)               │
                    ├── 等锁 ──→ 阻塞（BLOCKED）
                    ├── wait()/join() 无时限 ──→ 等待（WAITING）
                    ├── sleep(ms)/wait(ms) 有时限 ──→ 超时等待（TIMED_WAITING）
                    └── run() 执行完 ──→ 终止（TERMINATED）
```

**面试能讲清这几个转移就够**：

| 触发 | 从哪到哪 |
|---|---|
| `start()` | NEW → RUNNABLE |
| 抢 synchronized 锁失败 | RUNNABLE → **BLOCKED** |
| 拿到锁 | BLOCKED → RUNNABLE |
| `Object.wait()` | RUNNABLE → **WAITING**（释放锁！） |
| `notify()/notifyAll()` | WAITING → 重新抢锁 |
| `Thread.sleep(ms)` | RUNNABLE → **TIMED_WAITING**（**不释放锁**！） |
| run() 结束 | → TERMINATED |

> ⚠️ 必考对比：**sleep 不释放锁，wait 释放锁**。一句话：sleep 是 Thread 的静态方法，只是"我自己睡一会儿，怀里的锁不放"；wait 是 Object 的方法，必须在 synchronized 里调用，"我进等待池，锁交出来让别人用"。

## 三、synchronized：八股之王

### 3.1 三种用法（锁的对象不同！）

```java
synchronized(obj) { }              // ① 代码块：锁 obj 这个对象

public synchronized void m() { }   // ② 实例方法：锁 this（当前对象）

public static synchronized void sm() { }  // ③ 静态方法：锁 类.class（全局唯一）
```

**关键认知**：synchronized 锁的永远是**对象**（或类对象）。两个线程竞争的前提是**锁同一个对象**——锁不同对象 = 没锁。

### 3.2 底层：monitorenter / monitorexit + 对象头 MarkWord

每个 Java 对象的头里有一块 **MarkWord**，记录这个对象的锁状态。进入 synchronized 时（字节码指令 monitorenter），线程尝试把自己登记到 MarkWord 里；登记失败就排队阻塞。

### 3.3 锁升级（JDK6 后的优化，必考）

> 设计动机： heavyweight 锁要切换内核态，很贵。JVM 观察发现：很多锁其实**没竞争**或**竞争很轻**，没必要一上来就用最贵的。

```
无锁 → 偏向锁 → 轻量级锁 → 重量级锁
       （只能升级，不能降级——面试这么说即可）
```

| 状态 | 什么时候 | 干什么 |
|---|---|---|
| **偏向锁** | 只有一个线程用这把锁 | 在 MarkWord 记一下线程 ID，之后进出零成本 |
| **轻量级锁** | 出现第二个线程，但竞争很轻 | 失败者**自旋**（空转几圈再试），不阻塞不切内核态 |
| **重量级锁** | 竞争激烈 / 自旋失败 / 持有时间长 | 失败者进操作系统层面排队**阻塞**，等待唤醒 |

**一句话记住**：人少先记名字（偏向）→ 有点挤就在门口等一下（自旋/轻量）→ 实在挤不进就去排号睡觉（阻塞/重量）。

### 3.4 对比昨天学的

StringBuffer 单线程下不慢，就是因为锁优化：无竞争时锁停在偏向/轻量级，开销极小。**八股知识是连成网的**，面试时点出这种联系会大大加分。

## 四、volatile：最轻量的同步

### 4.1 它保证两件事

**① 可见性**

CPU 每个核有自己的缓存，线程读变量可能读的是缓存里的旧值。`volatile` 变量：**写后立即刷回主存，读时强制从主存读**——一个线程改了，其他线程立刻看得到。

```java
// 没有 volatile：可能永远打印不出"结束"（另一线程改了 flag，本线程读缓存）
volatile boolean flag = false;

new Thread(() -> { while (!flag) { } System.out.println("结束"); }).start();
Thread.sleep(1000);
flag = true;
```

**② 禁止指令重排**

编译器和 CPU 会为了性能打乱指令顺序（单线程下无影响，多线程可能出事）。volatile 通过**内存屏障**禁止它前后的读写被重排。

### 4.2 它不保证：原子性（必考陷阱）

```java
volatile int count = 0;
count++;   // ❌ 不是原子的！实际是 读→加→写 三步
```

两个线程同时 `count++`，各读各的、各加各的，最后丢一次更新。**volatile 管"看得见"，不管"一起改"**。要原子性：synchronized / AtomicInteger（CAS）。

### 4.3 经典应用：双重检查锁单例（DCL）

```java
class Singleton {
    private static volatile Singleton instance;   // volatile 必须有！

    static Singleton getInstance() {
        if (instance == null) {                    // 第一次检查（无锁，快）
            synchronized (Singleton.class) {
                if (instance == null) {            // 第二次检查（只有第一个进来的线程会创建）
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

**为什么这里 volatile 不能省**（高频追问）：`new Singleton()` 不是一步——① 分配内存 ② 初始化对象 ③ 把引用指向内存。指令重排可能变成 ①③②：另一个线程第一次检查时看到**引用不为 null 但对象还没初始化**，拿到一个"半成品"。volatile 禁止重排，堵上这个洞。

## 五、本日知识地图

```
线程
├── 创建：Thread / Runnable / Callable(有返回值) / 线程池
├── start() vs run()：start 才开新线程，只能调一次
├── 六状态：NEW/RUNNABLE/BLOCKED/WAITING/TIMED_WAITING/TERMINATED
└── sleep 不释放锁 vs wait 释放锁

synchronized
├── 锁的是对象：代码块锁指定对象，实例方法锁 this，静态方法锁 Class
├── 底层：monitorenter/exit + 对象头 MarkWord
└── 锁升级：无锁→偏向→轻量(自旋)→重量(阻塞)，只升不降

volatile
├── 保证：可见性 + 禁重排
├── 不保证：原子性（count++ 会丢更新）
└── 应用：DCL 单例（防"半成品对象"）
```
