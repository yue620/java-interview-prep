## 〇、先搞懂：线程是什么？为什么要学它？

**类比**：程序是一家餐厅。

- **进程** = 整个餐厅（有自己的厨房、桌椅、账本 → 内存空间）
- **线程** = 餐厅里的**服务员**。一个餐厅可以有多个服务员同时干活，他们**共用**厨房和账本（同一个进程的内存）

单线程程序 = 只有一个服务员：点单、做菜、上菜全一个人干，客人多了就排队。

多线程 = 多个服务员同时干活，**快**——但麻烦也来了：两个服务员同时改同一本账（共享变量），账就乱了。**并发编程学的就是"怎么让多个服务员干活又快又不乱"**。

Java 面试问并发，就是在问：你知道账本会乱吗？你知道怎么防吗（锁）？防的工具都有哪些坑吗？

## 一、创建线程：从"能跑起来"开始

### 1.1 先感受：不用线程 vs 用线程

**示例 1：单线程——两件事只能先后做**

```java
public class SingleThread {
    public static void main(String[] args) {
        for (int i = 0; i < 3; i++) {
            System.out.println("做菜 " + i);
        }
        for (int i = 0; i < 3; i++) {
            System.out.println("上菜 " + i);
        }
    }
}
```

输出（一定是这个顺序）：

```
做菜 0
做菜 1
做菜 2
上菜 0
上菜 1
上菜 2
```

**示例 2：多线程——两件事"同时"做**

```java
public class MultiThread {
    public static void main(String[] args) {
        // 创建一个新线程去"做菜"
        new Thread(() -> {
            for (int i = 0; i < 3; i++) {
                System.out.println("做菜 " + i);
            }
        }).start();

        // 主线程继续"上菜"
        for (int i = 0; i < 3; i++) {
            System.out.println("上菜 " + i);
        }
    }
}
```

输出（**每次运行顺序都不一样**，因为两个线程在交替执行）：

```
上菜 0
做菜 0
上菜 1
做菜 1
做菜 2
上菜 2
```

> 看到"输出顺序每次不同"，你就直观理解了并发：**两个线程谁先谁后由操作系统调度，不受你控制**。这既是多线程快的原因，也是一切 bug 的根源。

### 1.2 四种创建方式（逐个敲一遍）

**方式 ①：继承 Thread**

```java
class CookThread extends Thread {
    @Override
    public void run() {                    // 线程要干的活写在 run() 里
        System.out.println("新线程在做菜");
    }
}

public class Way1 {
    public static void main(String[] args) {
        new CookThread().start();          // start() 才真正启动新线程
    }
}
```

**方式 ②：实现 Runnable（推荐）**

```java
public class Way2 {
    public static void main(String[] args) {
        Runnable task = () -> System.out.println("新线程在做菜");  // lambda 简写
        new Thread(task).start();
    }
}
```

**方式 ③：Callable + FutureTask（能拿返回值）**

```java
import java.util.concurrent.*;

public class Way3 {
    public static void main(String[] args) throws Exception {
        Callable<Integer> task = () -> {
            Thread.sleep(1000);        // 假装算了 1 秒
            return 42;                 // Callable 可以有返回值！
        };

        FutureTask<Integer> ft = new FutureTask<>(task);
        new Thread(ft).start();

        System.out.println("主线程先干别的...");
        Integer result = ft.get();     // 阻塞在这里，等新线程算完
        System.out.println("拿到结果：" + result);
    }
}
```

输出：

```
主线程先干别的...
（等约 1 秒）
拿到结果：42
```

**方式 ④：线程池（先混个眼熟，Day 4 细讲）**

```java
import java.util.concurrent.*;

public class Way4 {
    public static void main(String[] args) {
        ExecutorService pool = Executors.newFixedThreadPool(2);
        pool.submit(() -> System.out.println("池里的线程在干活"));
        pool.shutdown();
    }
}
```

### 1.3 必考陷阱：start() 和 run() 的区别

**示例 3：亲自验证区别**

```java
public class StartVsRun {
    public static void main(String[] args) {
        Thread t = new Thread(() -> {
            System.out.println("run 方法运行在: " + Thread.currentThread().getName());
        }, "我的新线程");

        t.run();     // 直接调 run()
        t.start();   // 调 start()
    }
}
```

输出：

```
run 方法运行在: main        ← 直接调 run()，是 main 线程在执行！没有新线程！
run 方法运行在: 我的新线程   ← start() 才真正创建了新线程
```

> **面试答案**：`start()` 让 JVM 创建一个新线程去执行 run()；直接调 `run()` 只是当前线程里的普通方法调用，和并发没有半点关系。另外 start() 一个线程只能调一次，调两次抛 `IllegalThreadStateException`。

### 1.4 Runnable vs Callable（背这张表）

| | Runnable | Callable |
|---|---|---|
| 方法 | `run()` | `call()` |
| 返回值 | **没有** | **有** |
| 能抛受检异常 | 不能 | 能 |
| 怎么用 | 直接传给 Thread | 要包一层 FutureTask |

## 二、共享变量会"乱"成什么样（学锁之前先看灾难现场）

**示例 4：两个服务员同时记账——账乱了**

```java
public class RaceDemo {
    static int count = 0;   // 共享的账本

    public static void main(String[] args) throws InterruptedException {
        Runnable add = () -> {
            for (int i = 0; i < 10000; i++) {
                count++;    // 两个线程都在对同一个 count +1
            }
        };

        Thread t1 = new Thread(add);
        Thread t2 = new Thread(add);
        t1.start();
        t2.start();
        t1.join();          // join = 等 t1 干完
        t2.join();          // 等 t2 干完

        System.out.println("期望 20000，实际: " + count);
    }
}
```

输出（**每次都不一样，而且几乎总是小于 20000**）：

```
期望 20000，实际: 17352
```

**为什么少了？** `count++` 看着是一行，实际是**三步**：

```
1. 读 count 的值
2. +1
3. 写回 count
```

两个线程交错执行时就出事：

```
count 现在是 100
线程A：读到 100
线程B：读到 100      ← A 还没写回，B 也读了 100
线程A：+1 写回 101
线程B：+1 写回 101   ← B 也写 101！两次 +1 只涨了 1，丢了一次
```

> 这种现象叫**竞态条件（race condition）**，这种"读-改-写"三步操作叫**非原子操作**。记住这个示例——它是后面 synchronized、volatile、AtomicInteger 存在的全部理由。

## 三、synchronized：给账本配一把锁

### 3.1 一句话理解

synchronized = **一次只允许一个线程进入**的"单人结账台"。谁拿到锁谁进去改账，别人在门口排队（阻塞）。

**示例 5：用 synchronized 修复示例 4**

```java
public class SyncDemo {
    static int count = 0;
    static final Object lock = new Object();   // 专门用来当锁的对象

    public static void main(String[] args) throws InterruptedException {
        Runnable add = () -> {
            for (int i = 0; i < 10000; i++) {
                synchronized (lock) {   // 进结账台：一次只进一个线程
                    count++;
                }                       // 出来：锁自动还给下一个人
            }
        };

        Thread t1 = new Thread(add);
        Thread t2 = new Thread(add);
        t1.start(); t2.start();
        t1.join();  t2.join();

        System.out.println("期望 20000，实际: " + count);
    }
}
```

输出（**这次永远是 20000**）：

```
期望 20000，实际: 20000
```

### 3.2 三种用法——锁的对象分别是谁（必考）

```java
synchronized (lock) { }              // ① 代码块：锁你指定的对象（最灵活）

public synchronized void m() { }     // ② 实例方法：锁 this（当前对象）

public static synchronized void sm() { }  // ③ 静态方法：锁 这个类的 Class 对象（全局一把锁）
```

**示例 6：证明"锁不同对象 = 没锁"**

```java
public class WrongLock {
    static int count = 0;

    public static void main(String[] args) throws InterruptedException {
        Runnable add = () -> {
            for (int i = 0; i < 10000; i++) {
                synchronized (new Object()) {  // ❌ 每次 new 一把新锁！
                    count++;                    //    等于没锁
                }
            }
        };
        Thread t1 = new Thread(add);
        Thread t2 = new Thread(add);
        t1.start(); t2.start();
        t1.join();  t2.join();
        System.out.println("实际: " + count);   // 又不到 20000 了
    }
}
```

> **核心认知**：锁要有效，所有线程必须抢**同一把**锁。示例 5 里 `lock` 是 static 的、全程序只有一个，所以有效；示例 6 每次 new 一把，各进各的门，形同虚设。

### 3.3 锁升级：JVM 的"看人下菜碟"（理解版）

重量级锁（让线程排队睡觉）要进出操作系统内核，**很贵**。JVM 观察发现：现实中很多锁根本没竞争。于是它把锁分成四档，**从轻到重逐步升级**：

```
无锁 → 偏向锁 → 轻量级锁 → 重量级锁
```

用"单人结账台"类比：

| 锁状态 | 场景 | 类比 |
|---|---|---|
| **偏向锁** | 一直只有同一个线程来 | 常客来了直接进，门口记一下他的名字，下次免登记 |
| **轻量级锁** | 偶尔有第二个人来，但错得开 | 门口稍等转两圈（**自旋**），里面的人马上出来，不用排队睡觉 |
| **重量级锁** | 一堆人挤着抢 | 排队取号睡觉（**阻塞**），轮到你了操作系统叫醒你 |

> **面试一句话**：JDK6 后 synchronized 做了锁升级优化：无竞争时偏向锁零开销，轻竞争时自旋不阻塞，真激烈才升级成重量级锁进内核态排队。只能升级不能降级。这也是 StringBuffer 单线程下不慢的原因——锁停在轻量级。

### 3.4 sleep 和 wait 的区别（必考，用示例感受）

**示例 7：sleep 抱着锁睡觉**

```java
public class SleepHoldLock {
    static final Object lock = new Object();

    public static void main(String[] args) {
        Runnable r = () -> {
            synchronized (lock) {
                System.out.println(Thread.currentThread().getName() + " 拿到锁，睡 2 秒");
                try {
                    Thread.sleep(2000);     // 睡觉，但锁还抱在怀里！
                } catch (InterruptedException e) { }
                System.out.println(Thread.currentThread().getName() + " 醒了，放锁");
            }
        };
        new Thread(r, "线程A").start();
        new Thread(r, "线程B").start();
    }
}
```

输出（注意：**B 一定等 A 睡完 2 秒放锁后才能进去**）：

```
线程A 拿到锁，睡 2 秒
（等 2 秒）
线程A 醒了，放锁
线程B 拿到锁，睡 2 秒     ← B 被挡了整整 2 秒
（等 2 秒）
线程B 醒了，放锁
```

> **对比记忆**：
> - `Thread.sleep(ms)`：我睡会儿，**锁不放**，别人干等
> - `obj.wait()`：我进等待室，**锁交出来**，别人可以进；等 `notify()` 叫我
>
> 所以 wait/notify 必须写在 synchronized 里（你得先持有锁才谈得上"交出锁"），sleep 在哪都能用。

## 四、volatile：一块"公告栏"

### 4.1 解决什么问题：你看不到我改的

CPU 为了快，每个核有自己的**缓存**。线程读变量可能读的是自己缓存里的旧值，另一个线程改了主存里的值，它看不见。

**示例 8：可见性问题（没有 volatile）**

```java
public class VisibilityDemo {
    static boolean running = true;   // 注意：没加 volatile

    public static void main(String[] args) throws InterruptedException {
        new Thread(() -> {
            System.out.println("子线程开始转圈，等 running 变 false");
            while (running) { }       // 一直读缓存里的 true，可能永远出不来
            System.out.println("子线程结束");
        }).start();

        Thread.sleep(1000);
        running = false;              // main 线程改了值
        System.out.println("main 已把 running 改为 false");
    }
}
```

可能的输出（**子线程那行"结束"可能永远不打印，程序卡死**）：

```
子线程开始转圈，等 running 变 false
main 已把 running 改为 false
（子线程还在读自己缓存里的 true，转圈到天荒地老……）
```

**修复**：`static volatile boolean running = true;`

加上 volatile 后：写的人**立刻把新值刷到主存**，读的人**每次都从主存读**——像一块公告栏，谁写了大家都看见。再跑示例 8，子线程 1 秒后正常结束。

### 4.2 volatile 管不了的：原子性（必考陷阱）

把示例 4 的 `count` 加上 volatile 再跑：

```java
static volatile int count = 0;   // 加了 volatile
// ... 两个线程各 count++ 一万次 ...
System.out.println(count);       // 还是不到 20000！
```

**为什么**：`count++` 是"读→加→写"三步。volatile 只保证"读的时候看到最新值"，但两个线程可以**同时读到同一个最新值**，然后各加各的——丢更新照旧。

> **一句话**：volatile 管"看得见"（可见性），不管"一起改"（原子性）。要原子性还是得 synchronized 或 AtomicInteger。

### 4.3 应用：双重检查锁单例（DCL）

**示例 9：能直接用的单例**

```java
public class Singleton {
    // ① volatile 必须有！原因见下
    private static volatile Singleton instance;

    private Singleton() { }   // 私有构造，别人 new 不了

    public static Singleton getInstance() {
        if (instance == null) {                    // ② 第一次检查：不为 null 就直接返回（不用抢锁，快）
            synchronized (Singleton.class) {       // ③ 抢锁
                if (instance == null) {            // ④ 第二次检查：可能等锁期间别人已经建好了
                    instance = new Singleton();    // ⑤ 只有真正第一个进来的线程会执行到这
                }
            }
        }
        return instance;
    }
}
```

**三个"为什么"（面试连环问）**：

1. **为什么要检查两次？** 第一次检查挡掉 99% 的调用（建好之后进来直接返回，不用抢锁）；第二次检查防"两个线程同时通过第一次检查，排队等锁，都进去 new"。
2. **为什么 volatile 不能省？** `new Singleton()` 实际三步：分配内存 → 初始化 → 引用指向内存。JVM 可能重排成"分配 → 指向 → 初始化"。这时另一个线程第一次检查发现引用不为 null，**直接返回了一个还没初始化的半成品对象**。volatile 禁止这种重排。
3. **构造为什么私有？** 不然别人随便 new，单例形同虚设。
