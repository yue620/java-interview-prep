# Day 7 自测清单答案（采分点版）

> 口述不用一字不差，命中加粗采分点即可得分。

**1. IoC 和 DI？关系？**
- IoC（控制反转）：**对象创建和管理的控制权**从代码交给 Spring 容器
- DI（依赖注入）：实现 IoC 的手段，**容器把依赖的对象注入**进来
- 关系：**IoC 是设计思想，DI 是具体实现方式**

**2. Bean 注解？区别？**
- `@Component`（通用）、`@Service`（业务层）、`@Repository`（DAO 层）、`@Controller/@RestController`（Web 层）
- **功能上等价**，区别在于**语义分层**，@Repository 额外带异常转换。也可通过 `@Configuration` + `@Bean` 方法注册（用于第三方类）

**3. 三种注入？为什么构造方法？**
- 字段注入（@Autowired 标字段）、setter 注入、构造方法注入
- 推荐构造方法：**依赖必填且一目了然**、字段可以 **final 不可变**、**启动时暴露循环依赖**、方便单元测试手动 new 传参

**4. 默认作用域？单例线程安全吗？**
- 默认 **singleton**（容器级唯一）
- **不保证线程安全**。无状态（无可变成员变量）的单例是安全的；有可变成员变量则不安全，解法：**ThreadLocal** 或改用局部变量/prototype

**5. Bean 生命周期主线**
- **实例化（构造）→ 属性填充（DI）→ Aware 回调 → BeanPostProcessor 前置 → 初始化（@PostConstruct/afterPropertiesSet/init-method）→ BeanPostProcessor 后置 → 使用 → 销毁（@PreDestroy/destroy）**

**6. BeanPostProcessor？AOP 代理位置？**
- 在**初始化前后**各有一次回调（postProcessBefore/AfterInitialization）
- AOP 代理在**后置处理**中生成并返回，替换原始 Bean 放进容器

**7. 循环依赖 + 三级缓存流程**
- A 依赖 B、B 依赖 A（单例 + setter/字段注入时可解决）
- 三级缓存：一级**成品**、二级**半成品早期引用**、三级**对象工厂**（支持 AOP 代理）
- 流程：**A 先实例化 → 工厂放三级缓存 → A 填充属性需要 B → 创建 B → B 从三级缓存拿 A 早期引用（升入二级）→ B 完成进一级 → 回填 A → A 完成**

**8. 解决不了的循环依赖？**
- **构造方法循环依赖**：两边都在构造时就要对方，**连裸对象都实例化不出来**，三级缓存无从下手，启动报 `BeanCurrentlyInCreationException`
- prototype 作用域的循环依赖也解决不了

**9. AOP 底层？两种代理区别？**
- 底层是**动态代理**：你拿到的 Bean 是代理对象，方法调用先经过代理织入通知
- JDK 动态代理：基于**接口**（反射生成接口实现类），目标必须实现接口
- CGLIB：基于**继承**（字节码生成子类），无需接口但不能代理 **final**；**Spring Boot 2.x+ 默认 CGLIB**

**10. 自调用为什么失效？**
- 增强逻辑在**代理对象**上；`this.foo()` 中 this 是**原始对象**，绕过了代理，通知/事务不会触发
- 解法：注入自身代理（`@Autowired` 自己）、通过 `AopContext.currentProxy()`、或拆分到另一个 Bean 调用

## 满分口述模板示例（第 7 题）

"循环依赖就是 A 依赖 B、B 依赖 A。Spring 用三级缓存解决单例 setter 注入的循环依赖：A 先实例化出裸对象，把对象工厂放进三级缓存；A 填充属性时发现需要 B，就去创建 B；B 填充属性时需要 A，从三级缓存拿到 A 的早期引用放进二级缓存，B 完成创建进入一级缓存；再回到 A 注入完整的 B，A 完成。但构造方法循环依赖解决不了，因为连裸对象都创建不出来，启动直接报错。"
