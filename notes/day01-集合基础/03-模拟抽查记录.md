# Day 1 模拟抽查记录（8/10）

> 7 道题，形式：面试官提问 → 口述作答 → 反馈 + 专题讲解 + 满分答案对照。
> 复习建议：先只看"题目"列自测，答不出再看反馈。

## 逐题记录

### 第 1 题：HashMap 底层数据结构（7/10）

**失误点**：树化阈值方向说反（是"达到 8"不是"超过 8"）；漏了退化阈值 6 及"8 和 6 之间留缓冲带"。

**满分要点**：数组+链表+红黑树；链表长度 ≥ 8 且数组长度 ≥ 64 才树化，数组 < 64 时优先扩容；树节点 ≤ 6 退化回链表；选 8 是负载因子 0.75 下泊松分布统计结果（概率 < 千万分之一）；查询 O(n) → O(log n)。

### 第 2 题：扩容机制（7/10）

**失误点**：主语说错——是 **`size`（元素个数）> 容量 × 0.75** 触发扩容，不是"数组大小"。

**满分要点**：新建 2 倍数组；JDK8 高低位拆分：`hash & 旧容量 == 0` 留原下标，≠ 0 移到 原下标+旧容量；不用重算 hash、尾插保持顺序。

### 第 3 题：JDK7 头插法死循环（专题讲解）

**核心链条**：头插法 → 遍历旧链表逐个插到新链表头部 → 顺序反转（A→B→C 变 C→B→A，像一摞盘子挪到旁边）→ 并发时线程 1 中途挂起、保存的 next 引用过期 → 线程 2 完成扩容后链表已反转 → 线程 1 醒来继续头插 → 两节点互指成环 → get 时无限循环 CPU 100%。JDK8 尾插法保持顺序，不会成环。

### 第 4 题：ConcurrentHashMap JDK7 vs JDK8（6/10）

**失误点**：JDK7 是**分段锁（Segment，默认 16 段）**，不是"线程锁"。

**满分要点**：JDK8 = CAS + synchronized：空桶插入用 CAS 无锁（CPU 指令级原子"比较并交换"，失败自旋重试不挂起）；桶非空用 synchronized **只锁该桶头节点**，不同桶完全并行；get 无锁（volatile 保证可见性）；扩容时其他线程协助搬迁（头节点 hash = -1 / MOVED）。

### 第 5 题：为什么重写 equals 必须重写 hashCode（4/10）⚠️ 最弱

**失误点**：只说了"hash 不同"，没说因果链和后果。

**"两道门"模型**：HashMap 判断 key 相同 = 第一道门 hashCode 相同（定位到同一个桶）→ 第二道门 equals 为 true（桶内确认）。只重写 equals → 两个逻辑相等的对象 hashCode 不同 → 分到不同桶 → put 进 13 号桶、get 去 4 号桶找 → 返回 null，数据丢失。反向不成立：hashCode 相同 equals 可以 false（即哈希冲突）。

### 第 6 题：ArrayList vs LinkedList（5/10）

**失误点**：LinkedList 底层是**双向链表**（Deque 只是它实现的接口）；"查询插入无太大区别"是硬错误——查询 O(1) vs O(n) 差异巨大。

**满分要点**：ArrayList 查询 O(1)、默认 10、1.5 倍扩容拷贝；LinkedList 查询 O(n)、头尾增删 O(1)，但**中间插入也要 O(n)**（定位需遍历）。实际开发几乎总选 ArrayList：连续内存对 CPU 缓存友好；队列语义用 ArrayDeque。

### 第 7 题：(n-1) & hash 与 2 的幂（8/10）

**补充论证**：2 的幂减 1 是"低位全 1"（16 → 01111），& 运算 = 取低 4 位 = 等价取模且分布均匀；非 2 的幂（如 10 → 01001）中间有 0，大量下标永远算不出，桶浪费、冲突加剧。

## 总评

**优点**：主干框架都在；敢问不懂的点（高低位拆分、头插法反转都是当场问当场学会的）。

**待改进**：
1. 说精确名词：size 不是"数组大小"、分段锁不是"线程锁"、双向链表不是"双端队列"
2. 回答带完整因果链和后果：如"hash 不同 → 落不同桶 → get 返回 null，数据丢失"
