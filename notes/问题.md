## 一、Spring 篇（Day 7-8）

### Q1：IoC 这个词到底怎么读、是什么意思？

**人话**：读作 "I-O-C"，三个字母分开念。全称 Inversion of Control（控制反转）。
**解释**：以前你写 `new UserService()`，是你（代码）控制对象的创建；用了 Spring，变成容器帮你创建好、你需要时直接给你 —— 控制权从你手里"反转"到了容器手里。
**面试怎么说**："IoC 是控制反转，把对象创建和依赖管理的控制权交给 Spring 容器；DI 依赖注入是它的实现方式。"

### Q2：Bean 是什么？和我 new 出来的对象有什么区别？

**人话**：Bean 就是"被 Spring 大管家登记在册的对象"。你自己 `new` 的对象 Spring 不认识，不管它死活；加了 `@Component/@Service` 注解的类，Spring 启动时会帮你 new 一个放进容器，谁需要就发给谁。
**关键区别**：Bean 默认全容器只有一个（单例），你 new 的对象每次都是一个新对象，且享受不到 AOP、事务这些增强。

### Q3：`@Autowired` 到底干了什么？

**人话**："自动装配"——你在字段/构造方法上标了它，Spring 启动时会去容器里找一个类型匹配的 Bean 塞进来。就像点外卖：你只声明"我要一份 UserRepository"，Spring 骑手给你送上门。
**注意**：Spring Boot 里如果构造方法只有一个，`@Autowired` 可以省略不写，也会自动注入。

### Q4：为什么构造方法循环依赖启动直接报错，setter 就可以？

**人话**：构造方法注入 = "我还没出生（new）就需要对方先存在"。A 出生需要 B，B 出生需要 A → 鸡生蛋死锁，谁都出生不了。
setter 注入 = "我先出生（裸对象 new 出来了），出生后再慢慢补填字段"。Spring 趁 A 裸对象刚 new 出来时把它放进三级缓存，B 就能拿到"还没填完字段的 A"先用着，死锁解开。
**面试怎么说**："构造注入时对象还没实例化完成就需要依赖，连半成品对象都放不进缓存；setter/字段注入可以先实例化出裸对象放进三级缓存，再回头填充依赖。"

### Q5：AOP 是干什么的？能不能举个最直白的例子？

**人话**：AOP = "批量给方法套壳"。比如你想给 50 个 Service 方法都加上"打印耗时"，笨办法是改 50 个方法；AOP 是写一个切面类，声明"service 包下所有方法执行前后帮我计时"，一处代码全部生效。
**生活类比**：小区门口的闸机 —— 居民（业务方法）不用关心闸机（切面），但每个人进出（方法调用）都会被闸机记录。

### Q6：代理对象是什么？为什么 `this` 调用会绕过它？

**人话**：Spring 给你注入的 Service **不是你写的那个类的本体，而是一个"套了壳的替身"（代理）**。你调 `userService.foo()`，实际是替身接的电话，替身先干拦截的活（开事务/记日志），再转给你写的真正方法。
而 `this.foo()` 里的 `this` 是**本体自己**，本体直接接的电话，替身压根不知道这通电话 → 壳里的功能（事务）全部失效。
**这就是 Day 8 所有事务失效场景的总根源。**

### Q7：CGLIB 怎么读？和 JDK 动态代理怎么区分记忆？

**读法**："C-G-lib"。
**记忆**：
- JDK 动态代理：**必须有接口**（它生成的是接口的实现类）—— 记"JDK 高冷，没接口不伺候"
- CGLIB：**不需要接口**（它生成的是你类的子类）—— 记"CGLIB 当你儿子，继承你的一切，但 final 方法继承不了"
- Spring Boot 2.x 之后默认 CGLIB。

### Q8：`@Transactional` 加了就万事大吉了吗？

**不是。** 它只在这五个条件都满足时才生效：
1. 方法是被 Spring 代理调用的（不是 this 自调用）
2. 方法是 **public**
3. 异常**抛出去**了（没被 catch 吞掉）
4. 异常是 **RuntimeException/Error**（或你配了 `rollbackFor = Exception.class`）
5. 数据库引擎是 **InnoDB**

记忆口诀：**"代理公开抛出去，运行时异常 InnoDB"**。

### Q9：传播行为是什么？为什么要有这个东西？

**人话**：方法 A（有事务）调方法 B（也有 @Transactional），B 怎么办？加入 A 的事务一起死，还是自己独立开一个？"传播行为"就是这个选择题的答案。
- 默认 `REQUIRED`：加入，同生共死（一条绳上的蚂蚱）
- `REQUIRES_NEW`：B 独立门户，A 回滚不影响 B（日志、审计场景用这个）

### Q10：Spring Boot 自动配置，能不能一句话说清楚？

**一句话**："Spring Boot 启动时扫描所有 jar 包里的自动配置清单文件（`AutoConfiguration.imports`），里面列着几百个配置类，每个都用条件注解把守（比如'classpath 里有这个类我才生效'、'用户自己没配过我才生效'），满足条件的就往容器注册默认 Bean。"
**所以**：你引了 `spring-boot-starter-web`，Tomcat、SpringMVC 就自动配好了；你自己定义了 DataSource，自动配置就让位（@ConditionalOnMissingBean）。

## 二、MySQL 篇（Day 9-10）

### Q11：B+ 树到底是什么？能不能别用术语解释？

**人话**：字典的目录页。查找"手机"这个词：
- 没有索引 = 从第 1 页翻到第 500 页逐字找（全表扫描）
- B+ 树索引 = 先查拼音目录 → 定位到"sh"区 → 再定位到具体页码，**翻 3-4 次就找到**
B+ 树的设计就两个心机：① 非叶子页只存目录不存内容 → 一页能塞更多目录 → 树更矮（翻得少）；② 所有内容页用链子串起来 → 找"sh 到 s 开头"的所有词时顺着链子捋就行（范围查询快）。

### Q12：回表是什么？为什么不好？

**人话**：用非主键索引查到了"目录页"，但目录上只写着"这条记录的主键是 1001"，具体内容还要拿 1001 去主键索引再查一次 —— 多跑了一趟，这趟就叫回表。
**优化**：如果你要的列索引里全有（`SELECT id, name`，索引正好是 name 建的），就不用回表，这叫**覆盖索引**，explain 里显示 `Using index`。

### Q13：最左前缀原则，我怕记不住，有没有口诀？

**口诀**："联合索引像查字典，先拼音后笔画"。
索引 `(name, price)`：先按 name 排，name 一样才按 price 排。
- `WHERE name='A'` ✅（有拼音）
- `WHERE name='A' AND price=100` ✅（拼音+笔画）
- `WHERE price=100` ❌（只给笔画，字典没法查）
**跳过最左边的列，后面全失效。**

### Q14：explain 是什么？怎么用？

**人话**：SQL 的"作战计划预览"。在任何 SELECT 前面加 `EXPLAIN`，MySQL 会告诉你它**打算怎么执行**这条 SQL：走不走索引、扫多少行。
**只看四列**：
- `type`：看到 `ALL`（全表扫描）= 报警；`ref/range/const` = 健康
- `key`：实际用的索引名，`NULL` = 没用索引
- `rows`：预计扫描行数，越小越好
- `Extra`：`Using index`（覆盖索引，好事）；`Using filesort`（额外排序，坏事）

### Q15：脏读、不可重复读、幻读，我总是混，怎么分？

**表格记忆法**：

| | 谁干的 | 发生了什么 |
|---|---|---|
| 脏读 | 别人 **update 还没提交** | 你读到了"将来会回滚掉的假数据" |
| 不可重复读 | 别人 **update 并提交了** | 你同事务里读**同一行**，两次值不一样 |
| 幻读 | 别人 **insert/delete 并提交了** | 你同事务里**同范围查询**，两次行数不一样 |

**口诀**："脏读读假钱，不可重复读是同一行变了，幻读是多出新行。"

### Q16：MVCC 到底是什么？undo log 版本链能再讲一遍吗？

**人话**：一行数据被反复修改，InnoDB 不覆盖旧值，而是把每个旧版本存进 undo log，用指针串成一串"历史档案"（版本链）。每个事务查询时拍一张"现在有哪些事务还没完事"的快照（ReadView），然后对着档案规则判断：这行数据是哪个版本是我该看到的？
**好处**：**读的人读历史档案，写的人写最新版本，互不排队**（读写不加锁）。
**RC vs RR 的唯一差别**：RC 每次查询都重拍快照（所以能看到别人新提交的）；RR 只在第一次查询拍一次，整个事务用同一张（所以两次读结果一样）。

### Q17：间隙锁锁的是"空气"？

**人话**：对，锁的就是"记录之间的空隙"。比如 id 有 1、5、10，你锁 5，间隙锁会把 (1,5) 和 (5,10) 这两个"空气区间"也锁住，**别人想 insert id=3 就会被堵住** —— 这就是 RR 级别防幻读的物理手段。
**记**：行锁锁记录，间隙锁锁空气，临键锁 = 记录 + 前面的空气（左开右闭），是 InnoDB RR 的默认加锁单位。

### Q18：乐观锁和悲观锁的区别，用一句话说？

- **悲观锁**："肯定会有人跟我抢，先锁门再办事" —— `SELECT ... FOR UPDATE`
- **乐观锁**："应该没人抢，先办事，提交时检查一下有没有被动过（version 版本号），被动过就重来"
乐观锁适合读多写少；悲观锁适合冲突激烈的场景。

### Q19：压测超卖时，为什么我电脑的库存没有变成负数？

可能原因排查：
1. 没有真并发 —— `curl` 循环要加 `&` 和 `wait` 才是并发，否则是串行 50 次
2. JPA 的 `save()` 在 `@Transactional` 里是事务提交时才真正 UPDATE，时序和想象不同 —— 确保 buyWrong 的读和写在同一个事务里
3. 库存基数太大 —— 库存设 5、并发 50 效果最明显

## 三、Redis 篇（Day 11）

### Q20：Redis 为什么快？我怕答不全

**四点，按顺序背**：
1. **纯内存**：数据在内存，不在磁盘（这是根本原因）
2. **单线程执行命令**：没有多线程的锁竞争和切换开销
3. **IO 多路复用**：一个线程同时监听上万个连接，谁有数据来了处理谁（像餐厅一个服务员盯着所有桌子，哪桌举手去哪桌，而不是一桌配一个服务员）
4. **数据结构高效**：SDS、跳表这些都是为速度设计的

### Q21：穿透、击穿、雪崩，名字太像了怎么区分？

**场景记忆法**：
- **穿透**：黑客拿**不存在的 id**（如 -1）狂刷你 → 缓存永远没这个数据 → 请求全穿透到 DB。**"穿" = 穿过缓存打到库**
- **击穿**：双 11 爆款商品的缓存**刚好过期那一瞬间**，一万人同时来 → 同时发现没缓存 → 同时去查库。**"击" = 一个点被集火**
- **雪崩**：你设缓存时偷懒全设了一样的过期时间，**凌晨 3 点集体过期** → 全站请求涌向 DB。**"崩" = 一大片一起塌**

| | 病根 | 解法 |
|---|---|---|
| 穿透 | 数据不存在 | 缓存空对象 / 布隆过滤器 |
| 击穿 | 一个热点 key 过期 | 互斥锁单线程重建 / 逻辑过期 |
| 雪崩 | 大量 key 同时过期 | 过期时间加随机值 / 高可用 |

### Q22：`SET key value NX PX 30000` 里 NX 和 PX 是什么？

- `NX`（Not eXists）：**key 不存在才能设置成功**。抢锁靠它 —— 第一个人设置成功（抢到锁），后面的人设置失败（没抢到）
- `PX 30000`：30000 毫秒后**自动过期**。防"抢到锁的人宕机了，锁永远不释放"（死锁）
**必须一条命令搞定**：拆成 `SETNX` + `EXPIRE` 两条的话，万一第一条执行完就宕机，锁成永久死锁。

### Q23：为什么解锁要用 Lua 脚本？直接 DEL 不行吗？

**不行，有两个坑**：
1. **会误删别人的锁**：你的锁 30 秒过期，你的业务跑了 35 秒 → 锁早过期了，别人已抢到同名锁 → 你执行完 DEL，把**别人的锁**删了
2. 所以要先 GET 比对"value 里存的 UUID 是不是我的"再删
3. 但"GET 比对"和"DEL"是两步，中间锁可能刚好过期被删 → 这两步必须原子执行 → **Lua 脚本在 Redis 里是原子执行的**，所以用 Lua

### Q24：Redisson 是什么？我自己写的锁不够用吗？

**人话**：Redisson 是别人封装好的"Redis 分布式工具箱"，分布式锁是它的招牌功能。
你手写的锁有一个解决不了的问题：**业务还没执行完，锁到期自动释放了**。Redisson 的**看门狗**：你持有锁期间，后台线程每 10 秒帮你"续租"一次，业务不结束锁不过期。
**面试话术**："简单场景 SET NX PX + Lua 够用；生产环境推荐 Redisson，它有看门狗自动续期、支持可重入。"

### Q25：为什么是"先更新数据库，再删缓存"，顺序反了会怎样？

**反过来的漏洞**（先删缓存，再更新数据库）：
1. 线程 A 删了缓存
2. A 还没来得及更新数据库，线程 B 来查询 → 缓存没有 → 查到**旧数据** → 写回缓存
3. A 这才更新数据库 → **缓存里躺着旧数据，数据库是新数据**，不一致了
**正着来**（先更新库再删缓存）也有极小窗口，但概率低得多；要更强就用延迟双删（更新完过几百毫秒再删一次）。

### Q25+：`HSET user:1 name "张三" age 20` 报错 `ERR wrong number of arguments for 'hset'`？

**原因**：你的 Redis 版本低于 4.0。**一条 HSET 同时写多个字段是 Redis 4.0 才支持**的；老版本 HSET 只接受 `HSET key field value` 恰好 3 个参数，多给就报参数个数错误。
（Windows 上很多人装的是微软移植的 Redis 3.0.504，特别容易踩到。）

**验证版本**：redis-cli 里执行 `INFO server`，看 `redis_version` 一行。

**解决办法（任选）**：
```bash
# 方法1：用 HMSET（专为多字段设计，老版本支持；4.0+ 已被 HSET 多参数取代但仍可用）
HMSET user:1 name "张三" age 20

# 方法2：拆成两条单字段 HSET
HSET user:1 name "张三"
HSET user:1 age 20
```
**长期建议**：升级 Redis（Windows 可用 tporadowski/redis 5.0.14 或 Memurai），面试和实际生产都是 5.x/6.x/7.x。

## 四、场景与项目话术篇（Day 12-13）

### Q26：面试官让我"设计一个秒杀系统"，我脑子一片空白怎么办？

**背下这个开头，后面的话会自己流出来**：
> "秒杀的核心矛盾是**瞬时洪峰 vs 数据库脆弱**，所以整体思路是把压力层层拦截，尽量不让流量打到数据库。我的架构是一个漏斗……"
然后从上往下数：前端限流 → 网关限流 → Redis 预减库存 → MQ 削峰 → 匀速落库。每一层说一句话作用，细节（幂等、防超卖、降级）等面试官追问再展开。

### Q27：MQ 我没实际用过，面试被问会不会露馅？

**策略**：MQ 以概念题准备（讲义 Day 12 第二节够用），被问"你项目用过 MQ 吗"时诚实回答：
> "我项目规模还没到需要 MQ 的程度，但消息丢失、重复消费、削峰这些核心概念我系统学习过，也了解秒杀架构里 MQ 的位置。如果有机会接触实际场景，我理解起来会很快。"
**诚实 + 展示了知识面，比硬编一个没用过的项目安全十倍。**

### Q28：自我介绍里的"钩子"是什么？

**人话**：故意在自我介绍里留一个"半句话"，勾引面试官追问你**准备得最充分**的内容。
比如："……其中我印象最深的是解决了缓存穿透的问题" —— 面试官大概率追问"怎么解决的？" → 正中下怀，把你 Day 11 练过的穿透三连（复现、空对象修复、布隆过滤器）倒出来。
**原则**：钩子的内容必须是你能讲 5 分钟不卡壳的；讲不清楚的，宁可不提。

### Q29：面试官问"你还有什么问题吗"，我该问什么？

**推荐**（显诚意）：
1. "团队目前的技术栈是什么？实习生会参与什么样的工作？"
2. "如果有幸加入，您建议我入职前补充哪方面知识？"
**避免**：薪资、加不加班（实习初面阶段不问）。

## 五、工具与环境篇（卡住了先查这里）

### Q30：IDEA 里 VM 参数在哪配置？

运行按钮旁边的下拉框 → **Edit Configurations（编辑配置）** → 选中你的启动类 → 找到 **VM options（虚拟机选项）**，没有的话点 **Modify options（Alt+V）** → 勾选 "Add VM options" → 填进去，如 `-Xmx20m -Xlog:gc*`。

### Q31：运行报"端口 8080 被占用"怎么办？

Git Bash 里执行：
```bash
netstat -ano | grep 8080        # 找到最后一列的 PID
taskkill //PID <PID号> //F      # 强制结束（注意是双斜杠）
```
或者去 application.yml 把 `server.port` 改成 8081。

### Q32：MySQL 连不上，报 "Access denied for user 'root'@'localhost'"？

`application.yml` 里的用户名密码和你本机 MySQL 不一致。打开 MySQL 客户端用同样的账号密码试登一次，确认正确密码后改 yml。

### Q33：Redis 连不上 "Connection refused"？

本机 Redis 没启动。找到你的 Redis 安装目录，启动 `redis-server.exe`；然后 `redis-cli.exe` 里敲 `ping`，返回 `PONG` 就是通了。

### Q34：Maven 依赖下载不动 / 一直转圈？

网络问题。给 Maven 配阿里云镜像：在 Maven 的 `conf/settings.xml`（或 IDEA 设置里指定的 settings 文件）的 `<mirrors>` 里加：
```xml
<mirror>
  <id>aliyun</id>
  <mirrorOf>central</mirrorOf>
  <url>https://maven.aliyun.com/repository/public</url>
</mirror>
```
然后 IDEA 里点 Maven 面板的刷新按钮重新加载。

### Q35：git push 又超时/失败了？

你的网络访问 GitHub 不稳定，已知 SSH 443 通道可用（已配置好）。push 失败就**原样重试 1-2 次**；反复失败的话检查是不是开了代理/关了代理，然后告诉 Kimi 帮你排查。

### Q36：中文注释在控制台输出是乱码？

Windows 控制台默认 GBK，Java 输出 UTF-8 就会乱。不影响功能；想修的话在 VM options 加 `-Dfile.encoding=UTF-8`，并且 IDEA 设置里 File Encodings 全部设成 UTF-8。
