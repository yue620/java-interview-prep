## A. Java 基础与集合

**1. HashMap 结构与树化**
- **数组+链表+红黑树**（JDK8）
- 树化：**链表长度 ≥ 8 且数组长度 ≥ 64**；数组不足 64 优先扩容；退化阈值 **6**

**2. 扩容**
- 触发：**size > 容量 × 0.75**；容量翻倍
- 重新分配：**高低位拆分**——`hash & oldCap`（旧容量）结果为 0 留在**原索引**，为 1 移到**原索引 + oldCap**；无需重新 hash

**3. 容量为 2 的幂**
- 定位用 `(n-1) & hash` 代替取模（位运算更快）
- n 是 2 的幂时 n-1 低位全 1，**& 等价于 %** 且分布均匀；扩容时才能用高低位拆分

**4. JDK7 死循环**
- JDK7 **头插法**，扩容迁移时链表**顺序反转**；并发下两个线程同时反转同一链表 → 形成**环形链表** → get 死循环 CPU 100%
- JDK8 改**尾插法**，迁移保持原顺序

**5. ConcurrentHashMap**
- JDK7：**Segment 分段锁**（默认 16 段）
- JDK8：**CAS + synchronized**：空桶 CAS 插入；非空桶 **synchronized 锁头节点**；锁粒度 = **单个桶**，并发度更高

**6. equals/hashCode**
- 契约：equals 相等 ⇒ hashCode **必须相等**
- 只重写 equals：HashMap 里逻辑相同的 key 因 hash 不同落到**不同桶**，get 不到、重复存储

**7. fail-fast**
- 迭代期间集合被**结构性修改** → modCount 与迭代器的 expectedModCount 不一致 → 抛 ConcurrentModificationException
- **是缺陷预警机制，不是线程安全方案**（抛异常不保证每次都发生）

**8. String 不可变 + 包装类缓存**
- 不可变好处：**线程安全 / 常量池共享 / hashCode 可缓存**
- `127 == 127` → **true**（-128~127 走 IntegerCache，同一对象）；`128 == 128` → **false**（超出缓存，new 了两个对象）

## B. 并发编程

**9. 线程创建方式**
- 继承 Thread / 实现 **Runnable**（无返回值、不能抛 checked 异常）/ **Callable + FutureTask**（**有返回值、可抛异常**）/ 线程池（生产正解）
- 推荐 Runnable：Java 单继承，实现接口更灵活，任务与线程解耦

**10. run vs start**
- run() = **当前线程**普通方法调用，不开新线程
- start() = 创建新线程执行 run；**同一线程对象 start 两次抛 IllegalThreadStateException**

**11. sleep vs wait**
- sleep：**Thread 静态方法**，哪里都能用，**不释放锁**，到时间自动醒
- wait：**Object 方法**，**必须在 synchronized 内**（持有锁才能调），**释放锁**，靠 notify/notifyAll 唤醒

**12. 锁升级**
- 无锁 → **偏向锁**（单线程，MarkWord 记线程 ID）→ **轻量级锁**（CAS 自旋）→ **重量级锁**（OS 互斥量，线程挂起）
- 目的：**按竞争激烈程度逐级增加开销**，低竞争避免重量级锁的昂贵成本

**13. volatile**
- 保证：**可见性** + **禁止指令重排**；不保证：**原子性**（i++ 是读-改-写三步）
- DCL 单例里：防止 `new` 的指令重排（分配内存→**初始化**→赋引用 被重排成 分配→赋引用→初始化），避免别的线程拿到**半初始化对象**

**14. CAS**
- CPU **原子指令**：比较内存值=预期值则换新值，无锁
- **ABA**：值被改走又改回来感知不到 → 加**版本号**（AtomicStampedReference）
- 高竞争替代：**LongAdder**（多个 Cell 分散竞争，sum 求和）

**15. 线程池**
- 7 参数：**核心线程数 / 最大线程数 / 空闲存活时间 / 单位 / 阻塞队列 / 线程工厂 / 拒绝策略**
- 流程：核心线程 → **队列** → 非核心线程（到最大）→ **拒绝策略**（默认 AbortPolicy 抛异常）
- Executors 问题：FixedThreadPool **队列无界**（堆积 OOM）、CachedThreadPool **线程数无上限**（创建过多线程 OOM）→ 手动 new ThreadPoolExecutor

**16. ThreadLocal 泄漏**
- Thread 内 ThreadLocalMap：**key 弱引用、value 强引用**
- key 被回收后 value 被 Entry 链强引用 → 线程池下线程不销毁 → **泄漏** → 用完 **remove()**

## C. JVM

**17. 内存区域**
- 共享：**堆**（对象）、**方法区**（类信息/常量/静态变量）
- 私有：**虚拟机栈**（栈帧）、本地方法栈、**程序计数器**（当前行号，线程切换恢复用）

**18. 垃圾判断**
- **可达性分析**：从 GC Roots（栈局部变量、静态变量等）出发，**不可达即垃圾**
- 不用引用计数：**循环引用**互相持有，计数永不为 0 → 漏收

**19. 复制算法**
- Eden + from/to 两个 Survivor（8:1:1）
- Minor GC：Eden + from 存活对象**复制到 to** → 清空 Eden 和 from → **交换 from/to**；对象朝生夕死，复制成本低、无碎片

**20. Minor vs Full GC + 直接进老年代**
- Minor：只收新生代，快；Full：整堆+方法区，慢且 STW 长
- 直接进老年代：**大对象**（超阈值）、**年龄到 15**（默认）、Survivor 放不下（动态年龄）

**21. 双亲委派**
- 加载请求**先委派父加载器**，逐层向上到 Bootstrap；**父能加载就父加载，父不行子才加载**
- 好处：避免**重复加载**；**保护核心类**（伪造的 java.lang.String 会被委派给 Bootstrap 加载正牌）

**22. MyClassLoader 实验（你自己的实操）**
- Hello.class 在 classpath 上 → 委派时**父加载器 AppClassLoader 先找到** → 轮不到自定义加载器
- 说明双亲委派"**父亲优先**"：父亲能加载，孩子永远没机会；移出 classpath 后父亲找不到才兜底调用 findClass

## D. Spring

**23. IoC/DI + 构造注入**
- IoC 是**思想**（控制权交容器），DI 是**实现**（容器注入依赖）
- 构造注入：**依赖必填、字段可 final、启动时暴露循环依赖、易测试**

**24. 单例线程安全**
- 不保证。**无状态**（无可变成员变量）的单例安全；有可变成员变量不安全 → 用局部变量 / ThreadLocal

**25. Bean 生命周期**
- **实例化 → 属性填充 → Aware 回调 → BeanPostProcessor 前置 → @PostConstruct 初始化 → BeanPostProcessor 后置（AOP 代理在此生成）→ 使用 → @PreDestroy 销毁**

**26. 循环依赖**
- 三级缓存：一级**成品** / 二级**半成品** / 三级**对象工厂**（支持代理）
- 流程：A 实例化→工厂入三级→A 需要 B→建 B→B 从三级拿 A 早期引用（升二级）→B 完成进一级→回填 A
- 无解：**构造方法循环依赖**（裸对象都造不出）+ prototype

**27. 代理与自调用**
- JDK 代理：基于**接口**；CGLIB：基于**继承**生成子类，不能代理 **final**；Boot 2.x+ 默认 **CGLIB**
- this 是**原始对象**不是代理 → 增强（事务/切面）全部绕过

**28. 事务失效（任 4）**
- **自调用**（绕过代理）/ **非 public**（CGLIB 无法增强）/ **异常被 catch 吞**（代理感知不到）/ **checked 异常**（默认只回滚 RuntimeException/Error，配 rollbackFor）/ **非 InnoDB**

**29. 自动配置**
- @EnableAutoConfiguration → 读 **`AutoConfiguration.imports`**（Boot2 是 spring.factories）→ **条件注解**（@ConditionalOnClass / @ConditionalOnMissingBean）过滤 → 满足条件的注册默认 Bean
- 自己定义了 DataSource → **不自动配**（@ConditionalOnMissingBean，**用户优先**）

## E. MySQL

**30. B+ 树淘汰链**
- 哈希：**不支持范围查询**和排序 → 淘汰
- 红黑树/二叉：树高 = **磁盘 IO 次数**，数据多树太高 → 淘汰
- B 树：**非叶子也存数据**，单节点存索引少、树偏高 → 淘汰
- **B+ 树：非叶子只存索引 → 矮胖（3-4 层装千万行）；叶子链表相连 → 范围查询顺链表扫**

**31. 回表与覆盖索引**
- 回表：二级索引叶子只存**索引列+主键**，要其他列得**拿主键再查一次聚簇索引**
- 覆盖索引：查询列**全在索引里**，不回表
- 判断：explain 的 **Extra = Using index**

**32. 最左前缀**
- 联合索引按 (a,b,c) 排序存储，查询**从最左列开始连续命中**才有效
- `where a=1 and c=1`：**只命中 a**，跳过 b 后 c 用不上索引

**33. 失效场景 + explain**
- 失效：列上**函数/运算**、**隐式类型转换**、**like '%xx'**、**违反最左前缀**、**or 带无索引列**
- explain 四列：**type**（ALL 报警，目标 ref/range 以上）、**key**、**rows**、**Extra**（filesort/temporary 坏，Using index 好）

**34. ACID 与隔离级别**
- A=**undo log**、D=**redo log**、I=**MVCC+锁**、C=三者共同保障的目标
- 级别：RU → **RC**（解决脏读）→ **RR**（解决不可重复读，InnoDB 临键锁基本解决幻读，**MySQL 默认**）→ 串行化

**35. MVCC**
- 三件套：**隐藏列**（DB_TRX_ID、DB_ROLL_PTR）+ **undo log 版本链** + **ReadView**
- RC vs RR 根因：**ReadView 生成时机**——RC 每次 SELECT 重新生成（能看别人新提交）；RR 第一次生成后复用（同事务两次读一致）

## F. Redis + 场景

**36. Redis 为什么快**
- **纯内存** + **单线程执行命令**（无锁无切换）+ **IO 多路复用** + 高效数据结构

**37. 穿透/击穿/雪崩**
- 穿透（**数据不存在**）：**缓存空对象** / 布隆过滤器
- 击穿（**热点 key 过期**）：**互斥锁单线程重建** / 逻辑过期
- 雪崩（**大量 key 同时过期**/宕机）：**过期时间加随机值** / 高可用 / 熔断限流

**38. Cache Aside**
- 读：先缓存 → 未命中查 DB → 回填缓存
- 写：**先更新 DB，再删除缓存**
- 删而非更新：避免并发写把**旧值盖回**；懒加载更省。先删缓存再更库有旧值回写窗口 → 所以先更库；要强一致用**延迟双删**/Canal

**39. 分布式锁**
- 三个点：① **SET NX PX 一条命令**（原子，防 SETNX 后宕机死锁）② value 存 **UUID**，解锁**先比对**（防误删别人锁）③ 比对+删除用 **Lua 保证原子**
- Redisson：**看门狗自动续期**（业务没完锁不过期）、可重入、锁等待

**40. 秒杀架构（采分层次）**
- 总思路一句：**把压力层层拦截，尽量不打到数据库**
- 漏斗：**前端**（按钮置灰/答题）→ **网关限流** → **Redis 预减库存**（DECR/Lua 原子）→ **MQ 削峰**（洪峰变匀速）→ 消费者匀速落库 → 用户轮询结果
- 加分细节：**幂等**（唯一索引/SETNX 防重复下单）、库存预热、降级兜底、超卖双保险（Redis 原子 + DB `stock>0`）
