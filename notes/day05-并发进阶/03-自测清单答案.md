# Day 5 自测清单 · 参考答案

> ⚠️ 规则不变：先口述，再对照。答案只列采分点。

---

**1. 为什么需要线程池？**

① 线程创建/销毁要和操作系统打交道，开销大，池化复用线程；② 线程数量失控会耗尽内存 CPU（默认栈约 1MB/个），池子限制最大线程数；③ 便于统一管理（监控、命名、拒绝策略）。

**2. 七个参数**

corePoolSize 核心线程数；maximumPoolSize 最大线程数；keepAliveTime + 单位：非核心线程空闲存活时间；workQueue 任务队列；threadFactory 线程工厂（命名等）；RejectedExecutionHandler 拒绝策略。

**3. 任务提交流程**

当前线程数 < core → 直接开新线程执行；否则队列未满 → 入队等待；队列已满且线程数 < max → 开非核心线程执行；都满 → 执行拒绝策略。
（关键顺序：先排队，队满才加临时工。）

**4. 拒绝策略**

AbortPolicy（默认）：抛 RejectedExecutionException；CallerRunsPolicy：提交者线程自己执行（减速不丢任务）；DiscardPolicy：静默丢弃新任务；DiscardOldestPolicy：丢队列最老任务再重试提交。

**5. 为什么禁用 Executors 快捷方法**

newFixedThreadPool 的队列容量是 Integer.MAX_VALUE（近似无界），任务堆积 → OOM；newCachedThreadPool 的 maximumPoolSize 是 Integer.MAX_VALUE，线程无限创建 → OOM。应手动 new ThreadPoolExecutor 明确 7 参数。

**6. CAS 是什么**

Compare And Swap，CPU 指令级原子操作：比较内存值是否等于预期，是则换成新值，否则失败。失败自旋重试，全程无锁、线程不阻塞，轻竞争下比 synchronized 快。AtomicInteger 等原子类底层就是 CAS + volatile。

**7. ABA 与高竞争**

ABA：值经历 A→B→A，CAS 只看现值发现不了中间变化 → 用 AtomicStampedReference 加版本号解决。
高竞争下 CAS 自旋空转耗 CPU → 计数场景用 LongAdder（多个计数单元分散竞争，最后求和）。

**8. ThreadLocal 是什么**

每个线程持有变量的独立副本，线程间互不可见。场景：存当前登录用户、请求 traceId、SimpleDateFormat（线程不安全类每线程一份）；Spring 事务、MDC 日志链路底层都是它。

**9. ThreadLocal 内存泄漏**

Thread 内部 Map 的 key 是 ThreadLocal 弱引用，value 是强引用。GC 回收 key 后 value 拿不到又删不掉 → 泄漏。线程池里线程复用，不 remove 还会让下个任务读到上次的脏数据。解决：用完在 finally 里 remove()。

**10. AQS**

AbstractQueuedSynchronizer，JUC 的地基。核心：一个 volatile int state 表示锁状态 + FIFO 等待队列；抢锁 = CAS 改 state，失败进队列阻塞，释放时唤醒队首。ReentrantLock、Semaphore、CountDownLatch 底层都是 AQS。
