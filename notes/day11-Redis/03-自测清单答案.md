# Day 11 自测清单答案（采分点版）

**1. 为什么快**
- **纯内存操作**；**单线程处理命令**（无锁竞争、无线程切换开销）；**IO 多路复用**（一个线程处理海量连接）；高效数据结构（SDS/跳表等）
- 单线程快的原因：瓶颈在**内存/网络带宽**而非 CPU，多线程反而引入锁和切换开销（Redis 6 后 IO 用了多线程，但命令执行仍单线程，加分项）

**2. 五大类型**
- String：缓存 JSON、计数器 INCR、分布式锁
- Hash：对象字段级读写（用户资料）
- List：简单消息队列、最新列表（quicklist）
- Set：去重、交集并集（共同好友）
- ZSet：**排行榜**、延迟队列，底层 **listpack + 跳表**（多层链表索引，O(log n)）

**3. RDB vs AOF**
- RDB：**定时全量快照**，恢复快、文件小，但可能丢失最后一次快照后的数据
- AOF：**追加每条写命令**，最多丢 1 秒（everysec），文件大恢复慢
- 生产：**混合持久化**（AOF 文件 = RDB 头部 + 增量命令）

**4. 穿透**
- 查询**数据库也不存在**的数据，缓存永远失效，请求全部打到 DB
- 解法：**缓存空对象**（短 TTL）/**布隆过滤器**前置拦截

**5. 击穿 + 与穿透区别**
- **某个热点 key** 过期瞬间，大量并发同时重建缓存打爆 DB
- 区别：穿透是"数据不存在"，击穿是"数据存在但热点 key 刚好过期"
- 解法：**互斥锁单线程重建** / **逻辑过期**（异步更新）

**6. 雪崩**
- **大量 key 同时过期**或 **Redis 宕机**，请求全涌向 DB
- 解法：过期时间**加随机值**打散；主从+哨兵保高可用；熔断限流兜底

**7. Cache Aside**
- 读：先缓存 → 未命中读 DB → **写回缓存**
- 写：**先更新 DB，再删除缓存**
- 删除而非更新：避免并发写把**旧值**盖回缓存；且缓存值可能是复杂计算结果，懒加载更省
- 先库后缓存有极小不一致窗口，强一致可用**延迟双删**或 Canal 订阅 binlog

**8. SETNX + EXPIRE 的问题**
- 两条命令**不原子**：SETNX 成功后宕机，锁永远无法释放 → 死锁
- 正确：`SET key uuid NX PX 30000` **一条命令**完成"抢锁+设过期"

**9. 误删别人的锁**
- value 存**唯一标识（UUID）**，解锁前**先 GET 比对**是不是自己的锁
- 比对+删除要**用 Lua 脚本**保证原子性，否则比对完锁刚好过期被删还是会误删

**10. Redisson 看门狗**
- 解决"**业务没执行完锁就过期**"：默认锁 30s，后台线程每 10s 检查，持有中自动**续期**
- 另外提供可重入、公平锁、锁等待等完整能力
