## 一、`==` 和 equals 到底比的是什么

**一句话：`==` 比的是"是不是同一个东西"，equals 比的是"内容一不一样"。**

但要分两种情况说清楚：

### 1.1 基本类型（int、char 等）

只有 `==`，比的就是值。没有 equals 这回事。

### 1.2 引用类型

```java
String a = new String("hello");
String b = new String("hello");

a == b        // false：两个不同的对象，堆里的两个地址
a.equals(b)   // true：内容一样（String 重写了 equals）
```

- `==` 比的是**引用（内存地址）**：两个变量指向堆里的同一个对象才为 true
- `equals` 默认（Object 里的版本）就是 `==`；**String、Integer 等重写了它**，改成比内容

### 1.3 高频陷阱：Integer 缓存（必考）

```java
Integer a = 127, b = 127;
a == b            // true ✅

Integer c = 128, d = 128;
c == d            // false ❌❌❌
```

**为什么**：`Integer a = 127` 是自动装箱，编译成 `Integer.valueOf(127)`。而 valueOf 对 **-128 ~ 127** 的整数有**缓存**——这个范围内的 Integer 对象复用同一个，所以 `==` 为 true；超出范围每次 new 新对象，`==` 就是 false。

> 一句话答案：**比较对象内容请用 equals；Integer 有 -128~127 缓存，这个范围内 == 碰巧为 true，范围外为 false，所以千万别用 == 比包装类。**

## 二、String 为什么是不可变的

### 2.1 什么是"不可变"

```java
String s = "abc";
s = s + "def";   // 看起来 s 变了？
```

**没有**。`"abc"` 那个对象还在原地，只是 `s + "def"` **新建了**一个 `"abcdef"` 对象，然后让 `s` 指向新对象。旧对象没人要了就等 GC。

String 内部是一个 `private final char[]`（JDK9 后是 byte[]），类本身也是 `final`，所有"修改"方法（concat、replace、substring）都返回**新对象**。

### 2.2 为什么设计成这样（三个理由，面试标准答案）

1. **字符串常量池需要它**：不可变才能安全地被多处共享（见 §三）
2. **hashCode 可以缓存**：String 的 hash 算一次就缓存住，所以它当 HashMap 的 key 又快又安全——如果内容能变，存进 HashMap 后内容一变，hash 变了，就再也找不到这个 key 了（回忆昨天的"两道门"）
3. **线程安全 + 安全敏感**：不可变对象天生线程安全；网络连接、文件路径、类加载用的都是 String，如果能被改掉是安全事故

## 三、字符串常量池（String Pool）

```java
String a = "hello";              // 字面量 → 进常量池
String b = "hello";              // 池里已有 → 直接复用
a == b                           // true ✅ 同一个对象

String c = new String("hello");  // new → 强制在堆里建新对象
a == c                           // false ❌
a.equals(c)                      // true
```

- **字面量**：编译期确定，进常量池（堆中的一块区域），相同内容只存一份
- **new String(...)**：不管池里有没有，都在堆里新建
- `c.intern()`：把 c 的内容塞进池里（如果池里没有），返回**池里的那份**

**面试经典题**：`String s = new String("abc")` 创建了几个对象？

> 答：**一个或两个**。常量池里已有 "abc" → 只 new 一个堆对象；池里没有 → 先在池里建一个，再 new 一个堆对象。

## 四、String、StringBuilder、StringBuffer 三兄弟

| | String | StringBuffer | StringBuilder |
|---|---|---|---|
| 可变性 | **不可变** | 可变 | 可变 |
| 线程安全 | 天然安全 | **安全**（方法都加了 synchronized） | **不安全** |
| 拼接性能 | 每次新建对象，慢 | 快 | **最快**（省了锁开销） |

### 面试标准场景题：循环里拼字符串用什么？

```java
// ❌ 慢：循环 1000 次就新建 1000 个 String 对象
String s = "";
for (int i = 0; i < 1000; i++) s += i;

// ✅ 快：就一个对象，在内部数组上追加
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 1000; i++) sb.append(i);
```

**选型口诀**：
- 不拼接 / 少量拼接 → String
- 单线程大量拼接 → **StringBuilder**（默认答案）
- 多线程共享拼接 → StringBuffer（实际很少见，因为通常不会让多线程拼同一个串）

> 加分细节：现代 javac 会把 `a + b` 这种**单行**拼接优化成 StringBuilder，但**循环里的 +=** 不会优化——每次循环还是 new 一个 StringBuilder。所以"单行用 + 无所谓，循环必须手写 StringBuilder"。

## 五、fail-fast：遍历集合时为什么不能删元素

### 5.1 现象

```java
List<String> list = new ArrayList<>(List.of("a", "b", "c"));
for (String s : list) {
    if (s.equals("b")) {
        list.remove(s);   // 💥 ConcurrentModificationException
    }
}
```

### 5.2 原理（一张图说清）

ArrayList 内部有两个计数：

- `modCount`：集合的**修改次数**（add/remove 都会 +1）
- `expectedModCount`：迭代器**创建时**记下的"我以为的修改次数"

```java
// 迭代器每次 next() 前都检查：
if (modCount != expectedModCount)
    throw new ConcurrentModificationException();
```

你用 `list.remove()` 改的是 modCount，迭代器的 expectedModCount 没更新 → 下次 next() 检查不通过 → 抛异常。

**设计理念**：宁可立刻抛异常（fail-fast），也不让你在数据不一致的状态下继续跑出莫名其妙的错误结果。

### 5.3 那遍历中想删元素怎么办（三个正确姿势）

1. **用迭代器自己的 remove**（它删除时会同步更新 expectedModCount）：

```java
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if (it.next().equals("b")) it.remove();   // ✅
}
```

2. **Java 8+ 一行流**：`list.removeIf(s -> s.equals("b"));` ✅
3. 多线程场景：用 `CopyOnWriteArrayList`（写时复制，改的时候拷贝新数组，遍历的旧数组不受影响）

### 5.4 追问：fail-fast 是线程安全机制吗？

**不是！** 它只是"尽量发现问题"的防御性检查，不保证一定能抛出。并发场景该用并发容器还是得用。

## 六、本日知识地图

```
== vs equals
├── ==：基本类型比值，引用类型比地址
├── equals：默认==，String/Integer 等重写为比内容
└── 陷阱：Integer 缓存 -128~127，包装类永远用 equals

String
├── 不可变：所有"修改"返回新对象
├── 为什么不可变：常量池共享 / hash 缓存 / 线程安全
├── 常量池：字面量进池复用，new 强制建新对象，intern() 入池
└── new String("abc")：1 或 2 个对象

拼接三兄弟
├── String：不可变，循环 += 每次新建对象 ❌
├── StringBuilder：可变、不锁、最快 → 默认选择
└── StringBuffer：可变、synchronized、线程安全

fail-fast
├── 原理：modCount ≠ expectedModCount → 抛 CME
├── 正确删除：迭代器 remove() / removeIf()
└── 注意：它不是线程安全机制
```
