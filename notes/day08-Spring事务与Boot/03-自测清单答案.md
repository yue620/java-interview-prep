# Day 8 自测清单答案（采分点版）

**1. 底层原理**
- **AOP 动态代理**：方法前开事务、正常返回 commit、抛异常 rollback。一切失效场景的总钥匙

**2. 四种失效场景（任答 4 个）**
- **自调用** this.xxx()：绕过代理
- **非 public 方法**：CGLIB 继承代理无法增强 private/final
- **异常被 catch 吞掉**：代理感知不到异常，正常提交
- **checked 异常**：默认只对 RuntimeException/Error 回滚
- **非 InnoDB 引擎**：存储引擎不支持事务
- （加分）方法所在类没被 Spring 管理（没注解、没被扫描到）

**3. 自调用解法（任 2）**
- 拆到**另一个 Bean**，注入后调用（最干净）
- **自己注入自己**（@Lazy 避免循环依赖），用代理调用
- `AopContext.currentProxy()`（需 @EnableAspectJAutoProxy(exposeProxy = true)）

**4. 默认回滚异常 + checked 处理**
- 默认 **RuntimeException 和 Error**
- 加 `rollbackFor = Exception.class`

**5. catch 吞异常的补救**
- catch 里 `TransactionAspectSupport.currentTransactionStatus().setRollbackOnly()` 手动标记回滚

**6. 传播行为 + REQUIRED vs REQUIRES_NEW**
- 传播行为：方法互相调用时，**事务如何传递**的规则
- REQUIRED：**有则加入，无则新建**（同生共死）
- REQUIRES_NEW：**挂起外层，新建独立事务**，自己 commit/rollback 不影响外层

**7. 日志保住的设计**
- 日志方法标 `@Transactional(propagation = REQUIRES_NEW)`，独立事务提交；主业务回滚不影响日志

**8. 三合一注解**
- `@SpringBootConfiguration`（= @Configuration，声明配置类）
- `@EnableAutoConfiguration`（**开启自动配置**）
- `@ComponentScan`（扫描本包及子包的组件）

**9. 自动配置流程**
- @EnableAutoConfiguration 导入自动配置选择器 → 读取各 jar 的 **`META-INF/spring/.../AutoConfiguration.imports`**（Boot 2.x 是 spring.factories）→ 拿到全部 XxxAutoConfiguration → 用**条件注解**（@ConditionalOnClass/@ConditionalOnMissingBean/@ConditionalOnProperty）逐个过滤 → 满足条件的注册默认 Bean

**10. 自定义 DataSource 后还会自动配吗**
- **不会**。`@ConditionalOnMissingBean` 检测到容器已有用户定义的 DataSource，自动配置退让——**用户优先**

## 满分口述模板（第 2 题）

"@Transactional 底层是 AOP 代理，所以失效场景都可以从'绕过代理'或'代理没生效'来解释：第一，自调用 this 是原始对象，绕过代理；第二，非 public 方法 CGLIB 无法通过继承增强；第三，异常被 catch 吞掉，代理感知不到异常就正常提交了；第四，默认只对 RuntimeException 回滚，checked 异常要配 rollbackFor；第五，数据库引擎得用 InnoDB。我在自己的 mini-mall 项目里把这几种都复现过，比如自调用那个，拆到另一个 Service 注入调用就解决了。"
