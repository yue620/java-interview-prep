## 〇、先搞懂：没有 @Transactional 的世界

转账：A 扣 100，B 加 100。第二步失败时，A 的钱已经扣了 —— 钱凭空消失。

```java
// 没有事务的日子：自己管 connection
Connection conn = dataSource.getConnection();
try {
    conn.setAutoCommit(false);
    // ... 执行两条 SQL
    conn.commit();
} catch (Exception e) {
    conn.rollback();    // 忘了写就完蛋
} finally {
    conn.close();
}
```

Spring 用**一个注解**接管这套样板代码：

```java
@Transactional
public void transfer(Long fromId, Long toId, int amount) {
    accountMapper.deduct(fromId, amount);   // 扣钱
    accountMapper.add(toId, amount);        // 加钱，这里抛异常 → 整个方法回滚
}
```

底层就是 Day 7 学的 **AOP 代理**：方法开始前开事务，正常返回就 commit，抛异常就 rollback。**记住"代理"两个字，今天所有失效场景都是因为它。**

## 一、@Transactional 失效场景 ⭐⭐必考

### 场景 1：自调用（最经典）

```java
@Service
public class OrderService {

    public void createOrder() {
        this.doCreate();   // this 是原始对象，绕过了代理 → 事务失效！
    }

    @Transactional
    public void doCreate() { /* 出错也不会回滚 */ }
}
```

**为什么**：`this.doCreate()` 里的 `this` 是 OrderService 本体，不是 Spring 生成的代理。事务增强只在代理对象上有。
**解法**：把 `doCreate` 挪到另一个 Service 注入调用；或注入自己（`@Lazy @Autowired OrderService self`）。

### 场景 2：方法不是 public

```java
@Transactional
private void doCreate() { }   // 不生效（CGLIB 代理无法增强 private）
```
Spring 只代理 **public** 方法（CGLIB 通过继承生成子类，private/final 方法无法被子类覆盖）。

### 场景 3：异常被 try-catch 吞掉

```java
@Transactional
public void create() {
    try {
        mapper.insert(order);
        int i = 1 / 0;
    } catch (Exception e) {
        log.error("出错了", e);   // 异常被吃掉，代理压根不知道出错了 → 正常提交！
    }
}
```
**解法**：catch 里继续 `throw new RuntimeException(e)`，或手动 `TransactionAspectSupport.currentTransactionStatus().setRollbackOnly()`。

### 场景 4：异常类型不对

```java
@Transactional   // 默认只对 RuntimeException 和 Error 回滚！
public void create() throws IOException {
    throw new IOException(" checked 异常默认不回滚！");
}
```
**解法**：`@Transactional(rollbackFor = Exception.class)`。

### 场景 5：数据库引擎不支持事务

MySQL 的 MyISAM 引擎不支持事务，注解写了也白写。用 **InnoDB**。

### 速记表

| 失效场景 | 根因 |
|---|---|
| 自调用 this.xxx() | 绕过代理 |
| 非 public 方法 | 代理无法增强 |
| 异常被 catch 吞 | 代理感知不到异常 |
| checked 异常默认不回滚 | rollbackFor 默认只有 RuntimeException/Error |
| 引擎非 InnoDB | 存储引擎不支持事务 |

## 二、事务传播行为：方法调方法时事务怎么办 ⭐

A 方法（有事务）调 B 方法（也有 @Transactional），B 是加入 A 的事务，还是自己新开一个？这就是**传播行为（Propagation）**。

```java
@Transactional(propagation = Propagation.REQUIRED)  // 默认值
```

记住 3 个就够用：

| 传播行为 | 含义 | 场景 |
|---|---|---|
| **REQUIRED（默认）** | 有事务就加入，没有就新建 | 绝大多数情况 |
| **REQUIRES_NEW** | 永远新建独立事务（外层挂起） | 记录日志：主业务回滚了，日志还要保住 |
| **NESTED** | 在外层事务里开"子事务"（savepoint），可单独回滚 | 局部可失败的批量操作 |

> 经典追问："主方法回滚，日志表能不能保住？"—— 日志方法标 `REQUIRES_NEW`，独立事务独立提交。

## 三、@Transactional 的其他关键属性

```java
@Transactional(
    propagation = Propagation.REQUIRED,       // 传播行为
    isolation = Isolation.READ_COMMITTED,     // 隔离级别（Day 10 详解，一般用数据库默认）
    rollbackFor = Exception.class,            // 指定哪些异常回滚
    readOnly = true,                          // 只读查询：给数据库优化提示
    timeout = 3                               // 超时秒数
)
```

## 四、Spring Boot 自动配置：为什么写个 starter 就能跑 ⭐

### 先看 @SpringBootApplication 是三合一

```java
@SpringBootApplication
// 等价于三个注解：
@SpringBootConfiguration   // 就是一个 @Configuration
@EnableAutoConfiguration   // ← 自动配置的总开关，核心在这
@ComponentScan             // 扫描本包及子包的 @Component/@Service...
```

### 自动配置原理（能口述这条链就够）

1. `@EnableAutoConfiguration` 会去所有 jar 包里找 **`META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`** 文件（Spring Boot 2.x 是 `META-INF/spring.factories`，面试提一嘴新旧两版加分）
2. 文件里列着几百个 `XxxAutoConfiguration` 配置类
3. 每个配置类头上挂着**条件注解**，满足条件才生效：

```java
@AutoConfiguration
@ConditionalOnClass(DataSource.class)        // classpath 里有 DataSource 才生效
@ConditionalOnMissingBean(DataSource.class)  // 你自己没定义过才生效（你的优先）
public class DataSourceAutoConfiguration { }
```

4. 条件满足 → 往容器里注册默认 Bean（比如自动配好 DataSource、RestTemplate）

> 一句话总结：**扫描 imports 文件 → 条件注解逐个过滤 → 满足条件的配置类注册默认 Bean，你自己定义了就以你的为准。**
> 这就是"引入 spring-boot-starter-web 就有内嵌 Tomcat"的魔法来源。

### 常见条件注解

`@ConditionalOnClass`（类存在）、`@ConditionalOnMissingBean`（Bean 不存在）、`@ConditionalOnProperty`（配置项匹配）—— 自己写 starter 时用。

## 五、配套小概念速记

- **starter**：打包好依赖 + 自动配置的"套餐"，如 `spring-boot-starter-web` = spring-web + spring-webmvc + 内嵌 Tomcat + jackson
- **application.yml 为什么能配一切**：自动配置类用 `@ConfigurationProperties` 绑定 yml 里的值
- **内嵌 Tomcat**：WebServerFactory 自动配置创建的，所以直接 `java -jar` 就能跑
