# ISSUE-001：手写一个简化版 HashMap（MyHashMap）

> 阶段 1 · Day 1（8/10）实践任务
> 对应八股：HashMap 底层结构、hash 扰动、扩容机制、链表/红黑树

---

## 一、需求描述

JDK 的 `HashMap` 你每天都在用，但面试官问你"底层怎么实现的"时，只说"数组+链表+红黑树"是不够的。本任务要求你**不看 JDK 源码，先凭理解手写一个简化版**，写完后再打开 `java.util.HashMap` 源码对照，找出自己和官方实现的差距。

## 二、接口要求

在 `collection/` 目录下新建 `MyHashMap.java`，实现以下接口：

```java
public class MyHashMap<K, V> {

    /** 存入键值对；key 已存在时覆盖旧值，并返回旧值；否则返回 null */
    V put(K key, V value);

    /** 根据 key 取值；不存在返回 null */
    V get(K key);

    /** 删除指定 key，返回被删除的值；不存在返回 null */
    V remove(K key);

    /** 当前存储的键值对数量 */
    int size();
}
```

## 三、验收标准（全部通过才算完成）

### 必做（Day 1 完成）

1. **底层结构**：`Node<K,V>[]` 数组 + 链表（不要求红黑树）
2. **hash 定位**：实现扰动函数 `(h = key.hashCode()) ^ (h >>> 16)`，再用 `(n - 1) & hash` 定位桶下标
   - 要求初始容量为 16，且容量始终是 2 的幂 —— 在注释里写清楚"为什么必须是 2 的幂"
3. **扩容**：负载因子 0.75，超过阈值后容量翻倍，并把旧数据 rehash 到新数组
4. **验证**：写一个 `main` 方法（或 `MyHashMapTest`）至少覆盖这些 case：
   - 存取 1000 个键值对后 `size() == 1000`，随机抽 20 个 key 取值正确（验证扩容没丢数据）
   - 重复 put 同一个 key，`size()` 不增加，get 返回新值
   - get / remove 一个不存在的 key，返回 null
   - remove 后 size 减 1，再 get 返回 null
   - `put(null, "x")` 能正常存取（想想 HashMap 为什么允许 null key）

### 挑战（有余力再做，Day 2 也可）

5. rehash 时用 **JDK8 的高低位拆分技巧**（`hash & oldCap == 0` 判断留在原下标还是移到 原下标+oldCap），而不是逐个重新计算下标
6. 链表长度 ≥ 8 且容量 ≥ 64 时打印一行日志提示"此处应转红黑树"（不用真实现红黑树，理解触发条件即可）

## 四、完成后的口述自检（对镜子/录音说一遍）

- [ ] 为什么用 `(n-1) & hash` 而不是 `hash % n`？
- [ ] 扰动函数为什么要右移 16 位异或？（提示：容量小的时候高位参与了运算吗？）
- [ ] 为什么负载因子是 0.75 而不是 1 或 0.5？
- [ ] 扩容时 rehash 的代价是什么？JDK8 怎么优化的？
- [ ] 为什么树化阈值是 8、退化阈值是 6？（泊松分布，能说出大意即可）

> 这 5 个问题就是面试官的连环追问套路。说不出来的，写进 `notes/错题本.md`。

## 五、提示（卡住再展开看）

<details>
<summary>提示 1：put 的基本流程</summary>

定位桶下标 → 桶为空直接插入新节点 → 桶非空则遍历链表：找到同 key 则覆盖，没找到则尾插到链表末尾 → size+1 → 判断是否超过阈值触发 resize。
</details>

<details>
<summary>提示 2：resize 的基本流程</summary>

新建 2 倍容量的数组 → 遍历旧数组每个桶的链表 → 每个节点用新容量重新定位 → 挂到新数组对应桶的链表上。
</details>
